# Project provenance and ownership

## Origin

This repository starts from the code and documentation of an earlier HANBAY
Hotel project developed by a five-member team. That inherited work includes the
initial frontend and backend structure, business modules, migrations, tests,
deployment assets and project documents.

The current repository imported that baseline in `Initial commit`
(`ec3c7c14bc63f206e8e38f94fcc1a5dce9de6ced`). The current two-member team does
not claim that inherited code was rewritten by them. New work should be
attributed through Git history from this baseline onward.

## Legacy material

Documents created for the earlier team remain in the repository when they are
useful as historical or technical evidence. In particular,
`docs/18-sprint-2-report-script.md` is a legacy sprint artifact and retains its
original author and participant names. Legacy documents must be clearly marked
and must not be used as the source of current team membership.

References to the earlier five-member setup in requirements are historical
context. The active team is the two maintainers listed above.

## Attribution policy

- Preserve author names and historical context in legacy artifacts.
- Do not relabel inherited implementation as work newly written by the current
  two-member team.
- Use commits and pull requests to record authorship of changes made after the
  imported baseline.
- Remove or replace obsolete personal contact and infrastructure details when
  they are operational data rather than authorship evidence.
- Record any future upstream import or third-party code with its source, license
  and import date.
